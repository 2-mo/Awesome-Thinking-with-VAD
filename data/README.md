# 视频异常理解研究地图：数据策展说明

`catalog.json` 是地图、论文目录、数据集页和阅读路线的单一数据源，结构遵循 `src/types.ts` 中的 `Catalog`。本轮于 **2026-09-29** 核验，收录 **17 篇核心论文、6 个数据资源、3 条阅读路线**。本目录仅收录直接研究视频异常的工作。这是围绕视频异常理解（VAU）的精选研究地图，不是完整论文数据库，也不提供跨协议排名。

## 收录与核验

- 核心论文直接研究视频异常检测、定位、解释、推理或异常理解评估。保留 TEVAD、VadCLIP 等必要前史，主体转向语言解释、因果理解、多粒度上下文和主动观察。
- 每篇 `sources` 保留核验使用的一手来源。标题、方法摘要、会议与年份以作者论文、正式论文集、arXiv 记录或作者仓库为依据；没有确认正式会议的工作标为 `arXiv`。正式发表年与最初 arXiv 年不同并非冲突，例如 VADER 为 WACV 2026。
- 核验覆盖书目信息、摘要／方法主张、被显式列出的数据集以及作者发布入口。它不代表复现实验、不保证外部页面始终可访问，也不把作者声称的性能优势当作本站验证结论。
- `mechanism` 是 6–10 字的编辑提炼，概括该论文的主要创新抓手，不代替正式方法名称或暗示论文继承。
- `summary` 概括论文贡献；`takeaway` 是编辑阅读提示；核心论文的 `limitation` 以“阅读关注”表述待检查的问题，不冒充作者承认的缺陷或已证实的失败。
- `links.code` 仅在可确认作者实现入口时填写；未核验的不猜测。PANDA 作者仓库核验时仍称代码即将发布，因此放在 `project`，不标为可用代码。
- 数据集数量、性能数字和具体拆分数未做全面复核，故不填入。`datasetIds` 只列当前来源明确支持的关联，空数组表示未在本轮建立关联，不表示论文没有实验。

本轮特别重新核对 LAVAD（arXiv:2404.01014）、Holmes-VAU（arXiv:2412.06171）、Ex-VAD（ICML 2025，PMLR `huang25ad`）与 MoniTor（arXiv:2510.21449），未继承旧页面的题名／链接映射。

## 地图语义

五个主题簇按**创新思路与机制**组织，不按数据集、论文年份或任务名称分组。它们形成编辑提出的问题进阶：**怎样表征 → 怎样建立判据 → 怎样组织时间 → 怎样补充观察 → 怎样推理与验证**。这个顺序是研究问题的组织方式，不声称后一个方法继承前一个方法，也不意味着历史上依次发生。

| 簇 ID / 名称 | 创新抓手 | 研究问题 | 论文归属及其主要依据 |
| --- | --- | --- | --- |
| `alignment` / 语义对齐与融合 | 字幕特征融合、跨模态对齐、运动语言监督 | 怎样得到异常相关的语义表征？ | TEVAD：字幕语义融合；VadCLIP：视觉语言双分支；Ex-VAD：解释文本融合与标签增强对齐；HAWK：运动信息融合及运动语言监督。 |
| `explanation` / 语言判据与提示优化 | 语言中介、规则归纳、引导问题优化 | 怎样构造场景适用的异常标准？ | LAVAD：帧字幕经时序聚合转为异常评分；AnomalyRuler：正常规则归纳与演绎；VERA：通过语言反馈学习引导问题。 |
| `understanding` / 时序分层与记忆 | 多粒度组织、事件边界、历史记忆、分层边界评估 | 判据作用于哪段时间，需要多少历史？ | Holmes-VAU：片段／事件／视频三级指令与聚焦采样；EventVAD：动态时空图及事件边界；MoniTor：在线分数队列与历史预测；VALU：语义层级下的异常边界与评估。 |
| `evidence` / 主动观察与工具决策 | 场景规划、工具调用、交互策略学习 | 证据不足时应继续看哪里、调用什么？ | PANDA：按场景规划与工具反思；Anom-π：推理和时间操作交替执行的策略。 |
| `reasoning` / 结构化推理与验证 | 问题分解、关系编码、反思修正、事实评估 | 如何组织推理并检验结论的依据？ | CUVA：事件／原因／后果分解与 MMEval；VADER：对象关系编码；SRVAU-R1：反思及修正训练；FineVAU：关键事实分解与 FVScore。 |

这个分类区分了两类贡献：**模型／推断机制创新**与**任务分解／评估协议创新**。CUVA、FineVAU、VALU 以后一类为主要收录理由，不能因为它们提出数据集，就把整张地图组织成数据集使用关系。`reasoning` 簇包含互补的推理组织和验证思路，并不宣称它们采用同一种算法。HAWK 按运动融合机制归类，而不是按“开放世界理解”任务归类。

每篇仅放入一个主要簇，不否认跨簇贡献。相关的 `summary`、`takeaway` 和论文来源用于解释具体归属。`position` 是 1200×850 地图坐标；主题距离不表示论文相似度、时间先后或影响力。

数据集及其 `uses` / `introduces` 关系保留为论文详情的来源依据，**不作为主图节点或主图连线**。主图若显示上述问题进阶，必须标为编辑组织的问题路径，不能标为 `extends` 或论文引用关系。

关系方向为 `source → target`：

- `uses`：论文明确使用某数据集；不意味着继承另一个方法。
- `introduces`：论文提出该数据资源。
- `extends`：仅在一手来源明确支持方法继承时使用；当前未绘制此类关系。


三条阅读路线按“研究问题—创新抓手—需要检查的证据”安排：从语义表征到异常判据、从时间组织到主动观察、从结构化解释到可检验结论。路线中的每一步解释该工作提供的具体新思路；它们是编辑安排的学习顺序，不是引用链或历史继承链。页面应保留关系证据，避免把视觉连接误读为已证实的研究谱系。

## 维护约定

新增或更新条目时先核对一手标题和链接，再写中文摘要；记录核验日期。任务标签统一使用：`异常检测`、`异常定位`、`异常解释`、`视频问答`、`异常推理`。数据集名称与方法名称相同时使用不同 ID，例如论文 `cuva` 与数据集 `cuva-dataset`。

修改完成后运行仓库的数据校验与构建命令。校验应覆盖唯一 ID、簇引用、数据集引用、关系两端、路线论文引用和来源 URL；它只能检查结构，不能替代内容核验。
